In one sentence: an agent is a model that can take multiple actions in a loop toward a goal — reading files, running commands, editing code, checking its own output — instead of just replying once to a single prompt. Quick check: "Skills run automatically whenever the model thinks they're relevant, without you asking."

False — skills run manually. You invoke them, or you explicitly ask the model to use one. They never silently trigger in the background; that's part of what keeps them legible.

Quick check: "Grill with Docs is a nice-to-have, mostly for advanced users."

False — it's recommended for everyone today, regardless of experience. It forces you to actually understand the codebase before touching it, and you leave with a real artifact (an ADR, a glossary) rather than just a demo.

🧭 New to this? What's a "TOML header" and why does it matter
Most of these skills store their metadata (name, description, when to use it) in a small header block at the top of the file, written in TOML or YAML — think of it like the label on a filing folder. The model reads just the header first to decide whether a skill is relevant. Only once it's actually invoked does the full body (the real instructions) get loaded. That's "progressive loading" — it keeps the model's context window from being clogged with instructions for skills it isn't using.
🚀 Stretch: push on this
Diff the header against the full skill body — roughly how much context does deferring the full body actually save? Could you sketch a one-paragraph header for a skill of your own, tight enough that a model could decide "relevant / not relevant" from it alone?
